# Archery 查询结果 CSV 导出脚本：说明与使用方法

## 用途与脚本位置

在 Archery 查询结果页面的浏览器 Console 中运行，把指定 Bootstrap Table 的查询结果导出为 CSV。脚本支持客户端分页和服务端分页；服务端模式会逐页加载，发现加载错误、超时或行数异常时停止，避免继续生成已知不完整的文件。

原始脚本：[archery-export-csv.js](<assets/Archery 查询结果 CSV 导出脚本/archery-export-csv.js>)。

归档保留用户提供的原始实现。以下说明基于代码静态分析与官方 API 文档；离线验证范围见文末。实际 Archery 部署版本、接口和页面行为仍需在使用环境中确认。

**导出范围是当前查询条件下，表格已经加载或分页接口能够返回的结果。** 脚本不会去掉 SQL 的 `LIMIT`、突破后端结果行数上限，也不会一次导出页面上的多个结果表。

## 快速使用

1. 在 Archery 中执行目标查询，等待结果表加载完成。
2. 打开浏览器开发者工具，进入 **Console**，确认执行上下文是结果表所在页面；若页面使用 iframe，选择表格所属的 frame。
3. 确认结果表的 HTML `id`。默认值是 `query_result1`，实际页面可能不同。可以在 Elements 中选中目标 `<table>` 查看，或运行下面的只读命令列出带 ID 的表格：

   ```javascript
   [...document.querySelectorAll('table[id]')].map(table => table.id)
   ```

4. 打开原始脚本，将开头的配置改成目标表格 ID；填写时不加 `#`：

   ```javascript
   const id = "query_result1";
   ```

5. 如果页面使用服务端分页，先在界面开启分页，并选择一个数字形式的每页条数；不要选择 `All` 或“全部”。客户端分页不要求这项设置。
6. 将修改后的**完整脚本**复制到 Console，按 Enter 执行一次。导出期间保持页面打开，等待完成，不操作查询、搜索、筛选、排序、翻页或列设置，也不重复执行脚本。
7. 服务端模式会输出进度，完成后触发 CSV 下载：

   ```text
   导出进度：1/3 页，100/250 行
   导出进度：2/3 页，200/250 行
   导出进度：3/3 页，250/250 行
   ✅ 导出完成：250 行（不含表头）
   ```

8. 到浏览器下载列表确认文件已保存，核对表头、记录数和少量关键字段。日志中的“完成”表示脚本已经生成文件并触发下载，不等于确认文件已落盘。

示例文件名：`query_result1_2026-10-16T02-30-00-000Z.csv`。文件名使用 `toISOString()` 的 UTC 时间；中国标准时间为 UTC+8，因此时间通常比本地时间早 8 小时。浏览器设置可能决定直接保存还是询问保存位置。

## 运行条件

- 使用支持 `async/await`、可选链 `?.`、空值合并 `??` 和 Blob 下载的现代浏览器。
- 页面存在 `window.jQuery`，且加载并初始化了 Bootstrap Table 插件；仅有普通 HTML 表格不够。
- 目标表格包含 `thead th[data-field]`，字段名能够直接对应行对象的属性。
- 服务端分页接口能够按页返回数据和准确的 `totalRows`，并触发标准的加载成功或失败事件。
- 数据量适合在浏览器内存中处理；脚本会同时保存 CSV 行文本、合并后的大字符串和 Blob，大结果可能卡顿或耗尽内存。

## 逻辑分析

| 阶段 | 实际行为 | 作用或边界 |
| --- | --- | --- |
| 环境检查 | 查找表格、jQuery 插件和 `bootstrap.table` 实例 | 页面、ID 或插件不匹配时提前报错 |
| 防重复运行 | 设置 `table.dataset.csvExporting` | 限制同一 DOM 表格重复运行；不会阻止手工翻页或其他刷新请求 |
| 获取列定义 | 遍历 `thead th[data-field]`，读取 `data-field` 和表头文字 | 固定本次导出的列及 DOM 顺序；表头无 `.th-inner` 时取整个 `th` 的文字 |
| 客户端模式 | 调用 `getData({ useCurrentPage: false, includeHiddenRows: true })` | 获取当前已加载数据中符合当前过滤状态的记录，包含隐藏行；不会主动加载后端其他数据 |
| 服务端模式 | 从第 1 页开始逐页 `refresh`，等待加载事件 | 每次先注册监听器再发起请求；后续页在上一页完成后额外等待 200 毫秒 |
| 完整性检查 | 首次加载后固定总行数，逐页检查页码、总行数和本页行数 | 任一不符合预期即停止；不能代替跨页数据快照或重复主键检查 |
| 生成文件 | 全字段双引号转义，CRLF 分隔记录，添加 UTF-8 BOM | 包含表头，正确包裹逗号、双引号和字段内换行 |
| 清理 | 加载结束后解绑监听器，主流程 `finally` 删除导出标记，下载后 60 秒释放对象 URL | 正常完成和主流程异常均解除锁；超时不会中止已经发出的网络请求 |

Bootstrap Table 官方说明中，`getData` 返回调用时已加载的数据，`useCurrentPage` 控制是否仅当前页，`includeHiddenRows` 控制隐藏行，`unfiltered` 才控制是否包含未过滤数据。本脚本没有设置 `unfiltered: true`。参见 [Methods：getData / refresh](https://bootstrap-table.com/docs/api/methods/)。

### 服务端分页示例

假设总行数为 250、每页 100 行：先加载第 1 页，取得并固定 `totalRows = 250`，计算得到 3 页，再依次校验并追加 100、100、50 行。第 2、3 页在请求前各额外等待 200 毫秒，每一页独立设置 60 秒加载超时。

总行数为 0 时仍会加载、检查第 1 页；返回空数组则生成仅含表头的 CSV。若某页失败，已经累积的内容只留在内存中，脚本不会下载部分结果。

### CSV 中的值如何处理

- 取值来自 `row[c.field]`，不是单元格 HTML 或 formatter 的显示文本。
- 每个字段先执行 `String(value ?? "")`，再将内部 `"` 变为 `""`，最后用双引号包裹。
- `null`、`undefined` 和缺失属性输出为空字段，与原本的空字符串无法区分；`0` 和 `false` 会保留。
- 字符串中的前导零、空白和换行保留在 CSV 文件中；对象通常变成 `[object Object]`，不会自动输出 JSON。
- 若数据在到达脚本之前已变成精度丢失的 JavaScript 数值，脚本无法还原数据库原值。需要保真的长 ID、精确小数等，应在查询或接口层返回字符串。

## 使用边界与注意事项

### 1. 行数校验不等于跨页内容一致

页码、总行数和每页行数都正确时，仍可能出现重复或漏行：例如分页期间数据发生变化但总行数不变、排序字段不唯一、接口忽略页码并反复返回同样数量的记录。脚本没有主键去重、内容校验或数据库快照机制。

对完整性要求高的结果，应使用稳定且唯一的排序；这只能降低翻页漂移，无法替代快照一致性。需要严格一致或数据量很大时，使用具备相应保证的服务端导出流程。

### 2. 同一张表的并发请求可能干扰事件等待

`.csvExport` 是监听器命名空间，便于清理，不是请求标识。脚本监听同一张表的下一次加载事件，无法证明该事件一定来自本次 `refresh`。导出前等待现有加载结束；若页面启用了自动刷新，先暂停它。导出期间不操作表格，可降低无关请求干扰的概率。

失败或超时会停止后续分页并解除导出标记，但未完成的请求仍可能稍后返回并更新页面。再次导出前，确认旧请求结束；必要时刷新页面并重新查询。

### 3. 表头顺序有明确适用范围

按当前 DOM 中所有 `thead th[data-field]` 导出，没有额外筛除隐藏列、复选框列、序号列或操作列；这些列是否进入 CSV 取决于实际 DOM。复杂多层表头或重复 `data-field` 也可能产生重复列。建议先检查表头，特殊列场景需另行适配。

`row[c.field]` 仅直接读取属性：`data-field="user.name"` 会读取名为 `user.name` 的键，不会自动解析 `row.user.name`。

### 4. CSV 双引号不指定 Excel 单元格类型

双引号用于 CSV 语法转义，不能保证 Excel 将字段按文本处理。长数字、带前导零的编号、类似日期的字符串仍可能被自动转换。需要保真时，使用 Excel 的文本/CSV 导入功能，在加载前把相关列设为“文本”；具体入口随版本不同而变化。参见 [Microsoft：保留前导零和大数](https://support.microsoft.com/en-us/excel/keeping-leading-zeros-and-large-numbers)。

原脚本也未对以 `=` 等字符开头的内容进行公式中和处理。若结果包含此类文本，应按文本导入并核对，CSV 转义本身不提供这项保证。

### 5. 页面状态不会自动恢复

服务端导出会实际刷新当前结果表，成功后通常停在最后一页，失败后停在最后尝试加载的页面；脚本没有保存和恢复原页码。页间等待 200 毫秒也不构成对后端查询成本或压力的保证。

## 可调整项

| 项目 | 默认值或位置 | 说明 |
| --- | --- | --- |
| 表格 ID | `const id = "query_result1"` | 日常使用通常只需修改此项 |
| 每页行数 | 读取 `options().pageSize` | 在页面分页控件中选择正整数；不要盲目改大 |
| 加载超时 | `loadPage` 中的 `60000` | 毫秒，针对每次加载；与末尾释放 URL 的 60 秒定时器用途不同 |
| 页间等待 | 翻到后续页之前的 `200` | 毫秒，在上一页完成后额外等待 |
| 导出文件名 | `a.download = ...` | 由表格 ID 和 UTC 时间组成，可按需要调整 |

## 常见报错与处理

| 现象或日志 | 可能原因与处理 |
| --- | --- |
| 未找到 Bootstrap Table 实例 | 检查表格 ID、页面/frame、查询是否完成，以及 jQuery 和插件是否存在 |
| 没有找到表头 | 检查目标是否为结果表，是否包含 `thead th[data-field]` |
| 正在导出，请勿重复执行 | 等待当前导出完成或报错；若页面被中断，重新加载页面并查询后再执行 |
| 请先开启分页，并选择数字类型的每页条数 | 服务端模式下，在页面开启分页并选择正整数条数 |
| 无法获取准确的总行数 | `totalRows` 无法转换为非负安全整数；检查接口及表格配置，不要通过删除校验继续导出 |
| 第 N 页加载失败/超时 | 查看页面状态和 Network 请求，排查会话、网络、接口和查询耗时；旧请求结束后再重试 |
| 页码或总行数发生变化 | 可能有手工操作、自动刷新、数据变化或分页适配问题；重新查询并保持操作条件稳定 |
| 应有 X 行，实际 Y 行 | 可能是接口限制、总数不准、分页参数不兼容或并发请求干扰；先查原因，不要跳过校验 |
| 显示完成但没有文件 | 检查浏览器下载列表、下载设置和拦截提示 |
| Excel 中编号变形或中文异常 | 通过文本/CSV 导入，选择 UTF-8、逗号分隔，并把编号等列指定为文本；BOM 不能保证所有应用行为一致 |
